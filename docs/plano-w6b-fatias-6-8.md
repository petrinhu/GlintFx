## 3. O contrato do laço, escrito para quem vai ler o cabeçalho sem nos conhecer

**Efeito para o consumidor, em uma frase:** ele escreve "prepare, depois a cada quadro faça isto e desenhe aquilo", e a biblioteca bombeia os eventos do sistema, mede o tempo decorrido (limitado, nunca negativo), diz se este quadro deve ser desenhado, apresenta na cadência real da tela, respeita um teto de quadros se ele pediu, e dorme quando a janela está oculta em vez de girar o processador. Quem prefere o próprio `while` chama `step()` e `present()` e recebe as mesmas garantias.

### 3.1 A superfície congelada (`include/glintfx/platform/loop/loop.hpp` e `include/glintfx/core/fixed_step.hpp`)

```cpp
// core/time.hpp (adição compatível, D-W6b-52)
[[nodiscard]] GLINTFX_API gltfx_time_point gltfx_now() noexcept;

// core/fixed_step.hpp (D-W6b-47) - value types do núcleo, layout visível
struct gltfx_fixed_step {
    gltfx_duration dt;                 // o passo fixo; <= 0 torna accumulate() um no-op total
    std::uint32_t max_steps;           // 0 = sem teto além do que o chamador já limitou
    gltfx_duration accumulated;        // estado; começa em zero
};
struct gltfx_fixed_step_result {
    std::uint32_t steps;               // quantos passos de dt executar agora
    gltfx_duration remainder;          // o que sobrou, exato (0 <= remainder < dt)
    double alpha;                      // remainder / dt, o "atalho" para interpolar
};
[[nodiscard]] GLINTFX_API gltfx_fixed_step_result
gltfx_fixed_step_accumulate(gltfx_fixed_step &step, gltfx_duration elapsed) noexcept;

// platform/loop/loop.hpp (D-W6b-41/42/43/48/54)
inline constexpr gltfx_duration k_gltfx_max_frame_elapsed{.nanoseconds = 250'000'000};

struct gltfx_frame_tick {
    gltfx_duration elapsed;            // desde o tick anterior, limitado a k_gltfx_max_frame_elapsed, nunca negativo; 0 no primeiro
    gltfx_time_point now;              // a leitura de gltfx_now() que fechou este tick
    std::uint64_t frame_index;         // 1 no primeiro tick, +1 a cada step(), sem buraco
    bool should_render;                // veja P4
    gltfx_present_outcome last_present;// o que present() devolveu da última vez; `presented` antes da primeira
};

struct gltfx_input_event;              // só declarado (D-W6b-24); a definição é de INPUT-EVENTS

struct gltfx_loop_callbacks {
    std::function<bool(const gltfx_frame_tick &)> on_frame;   // obrigatório; falso encerra run()
    std::function<void(const gltfx_frame_tick &)> on_render;  // obrigatório
    std::function<void(const gltfx_input_event &)> on_event;  // TEM de estar vazio nesta versão
};

struct loop_impl;
struct loop_internal_access;           // mesmo idioma dos outros três handles

class gltfx_loop {
  public:
    [[nodiscard]] GLINTFX_API static gltfx_rslt<gltfx_loop>
    open(gltfx_display &display, gltfx_window &window, gltfx_gl_context &context) noexcept;
    // move-only, destrutor RAII, mesma forma dos outros handles
    [[nodiscard]] GLINTFX_API bool is_open() const noexcept;
    [[nodiscard]] GLINTFX_API gltfx_rslt<gltfx_frame_tick> step() noexcept;
    [[nodiscard]] GLINTFX_API gltfx_rslt<gltfx_present_outcome> present() noexcept;
    [[nodiscard]] GLINTFX_API gltfx_rslt<void> run(const gltfx_loop_callbacks &callbacks) noexcept;
};
```

## 4. Tempo do mundo e tempo do desenho: a decisão, o custo, o que se perde

**A decisão (D-W6b-47):** o laço entrega **tempo do desenho** (o decorrido medido entre dois ticks, limitado), e o **tempo do mundo** é responsabilidade do consumidor, com um átomo puro do núcleo à mão: `gltfx_fixed_step`. O laço nunca chama a simulação do consumidor em passo fixo por conta própria.

**Por quê:** a L-02 do projeto proíbe regra de aplicação dentro da biblioteca, e "qual `dt` a física usa" é regra de aplicação. Um laço que impõe passo fixo obriga todo consumidor (inclusive quem só anima interface) a pagar acumulador e interpolação; um laço que não oferece o átomo empurra cada consumidor a reescrever a mesma espiral. O meio é o do mercado (§1).

**O que custa:** dois guardas (o limitador de 250 ms no laço e `max_steps` no átomo), um `double` de conforto (`alpha`) ao lado do `remainder` exato, e um parágrafo no header com a dor nomeada ("na máquina rápida o personagem pula mais alto").

**O que se perde:** não há `on_fixed_update` no `run()`; o consumidor que quer interpolação escreve três linhas com `alpha`. Um consumidor que ignora o átomo e integra física com `elapsed` cru tem comportamento dependente da máquina, e a biblioteca não tem como impedir, só avisar. Também se perde, de propósito, a `frames` da folha de estilo como "quadro real desta tela": ela é apelido de duração a 60 Hz (decisão 3 de 28/08) e será resolvida por `GFSS-RESOLVE` sobre `elapsed`, fora desta onda (§10).

## 7. Paridade (L-04): o laço igual nos cinco alvos, e as divergências contadas

A fachada do laço, o átomo do tick, o agendador do teto e a validação de callbacks são **um arquivo cada, sem `#if`**, compilados nos cinco sistemas; os únicos ramos por sistema são os dois adaptadores de display (`wait_events`) e os dois de contexto (`present_would_skip`). **Divergências inevitáveis, declaradas E contadas: 4.**

| # | Divergência | Lado que difere | Por que é inevitável | Como fica declarada |
|---|---|---|---|---|
| 1 | Oclusão por outra janela | Wayland pode reportar (compositor que estrangula); Windows não expõe | o sistema não afirma | linha da matriz (D-W6b-26), sem asserção |
| 2 | `state(suspended)` só com compositor v6 | Wayland | versão anunciada pelo compositor | asserção condicionada a `xdg_wm_base_version`, impressa na mesma linha |
| 3 | Primeira detecção de oculto com `vsync=off` custa até 100 ms de apresentações descartadas | Wayland (Windows: 0) | a sonda Wayland é por idade de callback; a Win32 é síncrona | `rendered_while_hidden_vsync_off` em `measured_exceptions.txt` (`ambos`), com o teto ≤ 6 asseverado só no Linux |
| 4 | Grão da espera sem timer de alta resolução | Windows pré-1803 | mecanismo do sistema | `high_resolution_wait` impresso; borda superior do teto (1500 ms) já o absorve |

**Ausências declaradas (não são divergência, são cobertura que não existe em nenhum dos dois lados):** perda de foco (§5, nenhum executor tira foco de propósito), suspensão do sistema. Entram em §10 como pendência, não em `parity_exceptions.txt` (o arquivo é para ausência de um lado só).
