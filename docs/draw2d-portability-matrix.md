# draw2d-portability-matrix.md

> **Audience: a consumer of this library, deciding whether to trust its 2D renderer on Linux and on Windows.** This document is written for that reader, not for this project's own contributors: every row below describes an EFFECT the consumer can observe by calling the public API (`glintfx::gltfx_renderer_2d`, `include/glintfx/draw2d/renderer_2d.hpp`, `frame_2d_report.hpp`), never an internal function name.
>
> It is the model `gl-loop-portability-matrix.md` already gives for the graphics context, and it holds itself to the same two house rules:
> 1. No sentence here claims equivalence, or divergence, that was not actually measured. Where the two systems have not been proven equal, that is written down as "not yet proven equal", never papered over with a plausible-sounding guess.
> 2. Every sentence that claims something was measured names the exact test that measured it. A sentence with no test named next to it is an opinion, not a measurement, and does not belong in this table.
>
> No volatile digit lives in this document (test counts, line numbers, run numbers, measured channel values): where a fact would need one, this document names the command or the test that produces it instead. The raw values the live test measures are printed by the test itself as `MEASURED draw2d_parity_test.<key>` lines, read from the CI log of each system.

## How the proof is split

Two kinds of proof sit behind every row, and they are different claims:

- **By construction, on all five systems.** The pieces of the renderer that are plain data (paint order, the transform, the vertex bytes, the report counters) are compiled and tested on every system against fakes: a fake graphics card, a fake context. They prove the rule, never what a real driver does with it.
- **Live, by reading pixels.** `tests/parity/draw2d_parity_test.cpp` uses only the public API, opens a real window and a real graphics context, draws, and reads the surface back with `glReadPixels`. On Linux it runs as a container fixture of that name, inside a nested compositor with a software rasterizer (what that combination can and cannot do is only ever stated here from a measurement); on Windows it runs as a normal test target. It is the only thing that proves the right picture reaches the surface.

## The matrix

| Effect a consumer observes | Linux (Wayland/EGL) | Windows (Win32/WGL) | Status |
|---|---|---|---|
| Pieces are painted by layer, then by order of submission; a higher layer lands on top whatever it was submitted after | The eight combinations of {no layer, equal layers, lower, higher} x {A then B, B then A} over two overlapping squares, read back at the pixel of the overlap. | The same test is registered and linked. | **The RULE is proven by construction on every system**: `draw_order_test` and `piece_list_test` (an allocator that refuses everything after the reserve does not change the order). **Proven live on Linux** by `draw2d_parity_test`, with a mutant that ignores the layer seen red. **Not yet read on Windows**: the result of the same cells on the Windows runner is read from its CI log, and until it is, the two are not proven equal. |
| The order does not cross `flush()` | The piece list empties at the barrier, so a later piece is painted over everything before it. | The same code. | **Proven by construction**: `renderer_2d_impl_test` (layers 5 then 1 around a flush, the last upload is the later piece). Not exercised live: no pixel cell reads across a flush. |
| A piece is placed by the batch transform in force when it was submitted, in double precision; changing batch moves nothing already submitted | The transform is applied before the graphics card sees the piece. | The same code, no `#if`. | **Proven by construction**: `quad_vertices_test` (a camera at a position single precision cannot hold still lands the piece on the exact pixel) and `renderer_2d_impl_test` (a batch changed after the piece leaves it where it was). |
| A half-transparent piece over a background, with no dark fringe | Blended with premultiplied alpha; the color is encoded to sRGB before blending when `srgb_framebuffer` is off. | The same program. | **The stored color is proven premultiplied by construction** (`triangle_batch_test`). **Proven live on Linux with the option off**: `draw2d_parity_test` reads a half-transparent white and a half-transparent red, asserts the expected channel within a tolerance and the other channels of the red exactly zero, with a mutant that blends with straight alpha seen red. **Not yet read on Windows.** |
| `srgb_framebuffer` on: blending in linear light, the surface encodes | **Not yet read live on Linux.** The option was refused there by this library's own Wayland/EGL adapter, not by the driver: it asked `eglChooseConfig` for the sRGB colorspace, an attribute EGL accepts only on a surface, and Mesa answered with a bad-attribute error that the adapter read as "no sRGB" (defect D-SRGB-1). The adapter now asks for the colorspace on the window surface, requires the extension, and reads the surface's colorspace back; the live read on the Linux fixture is pending. Until a run shows the on mode executing, the test prints a declared, counted absence (`MEASURED draw2d_parity_test.srgb_on_cells_absent`). | The same cells run wherever the driver offers the configuration. | **Not yet proven on either system.** What the adapter asks of EGL is proven without a driver: `egl_config_attribs_test` (the choose list never carries a colorspace, the window surface list carries it exactly when the option is on). Whether the on mode runs is read from `srgb_on_cells_absent` in the CI log of each system; a value that says the on mode did not run means it is proven nowhere and this row says so. |
| Hostile GL state planted before the frame (depth and stencil tests, a one-pixel scissor, front faces culled, a color mask off, blending swapped and the equation changed, wireframe polygon mode, rasterizer discard, logic op, alpha-to-coverage, a consumer framebuffer, a bound texture, a program in use) does not change the picture | The clear and the piece read back as the exact colors, and every mutant that stops the renderer from setting one of those states is seen red. | The same test. | **Proven live on Linux** by `draw2d_parity_test`. **Not yet read on Windows.** |
| After `flush()` and after `finish_frame()`, GL is left in the closed list of states the header names, and nothing else is promised | Every item of the list is read back with `glGetIntegerv` and `glIsEnabled` after each of the two calls, and a mutant that leaves the program bound is seen red. | The same test. | **Proven live on Linux** by `draw2d_parity_test`; **not yet read on Windows**. The sequencing is also proven against the fake card: `renderer_2d_impl_test`. |
| An empty frame reports all zeros and shows the clear color; a frame with no clear does not clear | Read back as pixels. | The same test. | **Proven live on Linux** by `draw2d_parity_test`; **not yet read on Windows**. |
| Two rectangles sharing an edge leave no gap and no overlap | Two half-transparent rectangles side by side, the whole row read back: a gap would read zero, an overlap a brighter value. | The same test. | **Proven live on Linux** by `draw2d_parity_test`; **not yet read on Windows**. |
| One draw call for many pieces of equal state | The count is read from the report and asserted. | The same code. | **Proven by construction** (`triangle_batch_test`, pieces of equal state are one run) and **live on Linux** (`draw2d_parity_test`, the count asserted and printed as `MEASURED draw2d_parity_test.draw_calls_100_pieces_srgb_off`). The number is printed for you to measure, never promised. **Not yet read on Windows.** |
| A piece with a value that is not a finite number, or a rectangle with a negative size, is refused, counted, and is not an error of the frame | The report counts it with the token of the first reason. | The same code. | **Proven by construction**: `frame_report_tally_test` and `renderer_2d_impl_test`. |
| Every piece ends in exactly one of four places, and the four counters add up | The report says how many pieces were drawn, refused, dropped for lack of memory, or dropped because the graphics side failed. | The same code. | **Proven by construction**: `frame_report_tally_test` and `renderer_2d_impl_test` (a failing flush and a refusing allocator, each read back as the sum of the four). |
| A card that refuses the frame's data, or runs out of memory, is reported at the end of the frame with the step and the GL error code; out of memory from the card is told apart from the library's own | `out_of_memory` for the card's out-of-memory error, `platform_failure` for the rest, with the token `vertex_upload`, `index_upload` or `draw`. | The same code. | **Proven by construction against a fake card**: `vertex_stream_test` and `renderer_2d_impl_test`. **No live cell makes a real driver fail**, so what a real driver reports is not proven on either system. |
| Opening over a context that is not open is refused by name; a missing GL function is `unsupported` and names the function | `invalid_argument` with the token `context`; the loader's not-found becomes `unsupported`, keeping the function name. | The same. | **Proven live on Linux** for the closed context (a moved-from context handle) by `draw2d_parity_test`; **proven by construction** for the loader's word: `gl_load_refusal_test`. The real `open()` over a driver that lacks a function is not exercised on either system. |
| Calling a method on a renderer that was moved from | A debug build stops with a named message; a release build compiles the guard away. | The same. | **Not proven by a test that runs it.** It is a documented precondition, the same shape `gltfx_display` already has. |

## What this document does not cover

Textures, text, shapes beyond the rectangle and the quadrilateral, additive blending and sorting by position belong to later units and are not described here: this matrix describes only the surface `include/glintfx/draw2d/` freezes today, and grows exactly when it does.

## How this document stays honest

Every row above is either "proven by construction, or live, by a named test", or "not yet proven", and neither state is final. The live test already runs on Linux; the Windows half of every live row is read from the CI log of the Windows runner, and a row moves to "proven identical" only when that log says so. A row that depends on a driver feature a runner does not have says so, and the absence is printed and counted by the test itself, never skipped in silence.
