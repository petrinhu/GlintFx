# L-04: "o comportamento deve ser igual em qualquer OS ... e cada
# fatia entregue prova isso em cada sistema"). Consumido por
# tests/tools/check_test_parity.py.
#
# Uma linha aqui declara que um nome de teste existe no inventario de
# UM sistema e nao existe no do outro, POR QUE ISSO E ACEITAVEL AGORA -
# nunca uma forma de calar o portao. Formato, um registro por linha,
# quatro campos separados por "|" (comentarios com "#", linhas em
# branco ignoradas):
#
#   nome_do_teste | sistema_onde_falta | gemeo | item
#
# - nome_do_teste: nome exato do caso ctest que falta de um lado.
# - sistema_onde_falta: "linux" ou "windows" - o lado que NAO tem o
#   caso.
# - gemeo: nome do mecanismo que cobre o mesmo comportamento no lado
#   que falta, ou a palavra "nenhum" quando genuinamente nao ha
#   nenhum (o caso e proprio de UM sistema por natureza, ex.: uma
#   sonda do ambiente Win32 do proprio runner). "nenhum" so e honesto
#   quando a ausencia e permanente por desenho - nunca use "nenhum"
#   para uma lacuna real ainda sem par.
# - item: o ID do item em TODO.md que rastreia o fechamento desta
#   lacuna, OU o sentinela SEM-PENDENCIA quando a assimetria e
#   permanente por desenho e nenhum item precisa rastrea-la (exige
#   gemeo=nenhum - GODS_LAWS.md L-32 proibe criar item novo em
#   TODO.md so para isto).
#
# A REGRA que este arquivo existe para provar (verbatim do CTO,
# TODO.md): "exececao que aponta para item marcado como concluido
# REPROVA, porque e exatamente a regra 'concluido sem par'". Isto
# significa, em pratica: quando o item que uma linha aqui cita fecha
# (vira Concluido em TODO.md), a linha correspondente tem que ser
# APAGADA deste arquivo NO MESMO commit que fecha o item - nunca
# deixada para tras. Se ela ficar, o portao reprova, porque uma
# excecao esquecida apontando para um item concluido e exatamente o
# sintoma que motivou esta fatia inteira (retrabalho de 02/09/2026:
# tres ondas fechadas com entrega existindo em um sistema so).
#
# O QUE NAO ENTRA AQUI: quando o par existe nos dois sistemas mas com
# NOME DIFERENTE (mecanismo diferente, cobertura igual - ex.:
# display_connect_failure_test no Linux e win32_display_connect_test
# no Windows, ambos ja registrados como ctest, WIN-DISPLAY concluido
# em 03/09/2026), a linha certa e um APELIDO em
# tests/parity_aliases.txt, nunca uma excecao aqui - uma excecao
# aponta para uma AUSENCIA aceita, um apelido aponta para uma
# PRESENCA sob outro nome. Ver o cabecalho daquele arquivo.
