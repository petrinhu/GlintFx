# A promessa publica de que o desenho e o bombeamento de eventos nunca
# prendem o aplicativo do consumidor (include/glintfx/platform/gl/
# context.hpp's own "NEVER blocks the process indefinitely";
# include/glintfx/platform/window/display.hpp's own "never stalls
# waiting for the display server") ja foi furada DUAS vezes por um
# ponto de espera sem teto que uma auditoria de cabeca nao viu (72754af
# consertou o primeiro; este arquivo nasceu do segundo, o gemeo em
# display_adapter.cpp::flush_with_retry() - a mesma L-17 que existe
# para impedir exatamente isso). Este manifesto e o portao que
# check_wait_points.py confere fazem a enumeracao NUNCA MAIS ser feita
# de cabeca: todo sitio de espera encontrado nos arquivos varridos
# PRECISA de uma linha aqui, e toda linha aqui PRECISA continuar
# aparecendo na arvore - as duas direcoes reprovam.
#
# Formato, um registro por linha, quatro campos separados por "|"
# (comentarios com "#", linhas em branco ignoradas):
#
#   arquivo | funcao | trecho literal da chamada | classe
#
# - arquivo: caminho relativo a raiz do repositorio.
# - funcao: nome da funcao onde o sitio vive (documentacao humana; o
#   portao nao confere este campo, so' os outros tres).
# - trecho literal da chamada: substring exata que precisa aparecer na
#   linha de codigo encontrada (comentarios ja descartados antes da
#   comparacao) - o MESMO texto que fez a agulha casar.
# - classe, uma de cinco:
#     teto-nosso              - orcamento nosso, explicito, sempre finito
#     teto-do-sistema         - bloqueia, mas por um periodo do sistema
#                               operacional/driver, nunca sem fim
#     sem-teto-fora-do-caminho - pode esperar sem fim, mas NUNCA roda no
#                               caminho que um consumidor percorre a
#                               cada quadro (open()/roundtrip() manual)
#     sem-teto-declarado      - pode esperar sem fim NO caminho de
#                               quadro, risco MEDIDO e nomeado, nao
#                               eliminado nesta fatia (ver o comentario
#                               do sitio no arquivo-fonte para o motivo
#                               e o que falta para fechar de vez)
#     nao-espera              - a chamada em si nao bloqueia (posta so'
#                               porque a agulha da varredura tambem
#                               precisa casar textualmente com ela)
#
# ESCOPO DESTA VARREDURA: os quatro adaptadores que hoje tocam o
# sistema operacional para abrir/bombear a conexao e apresentar um
# quadro, mais o atomo compartilhado que display_adapter.cpp e
# egl_context_adapter.cpp agora chamam os dois para a mesma espera de
# escrita (bounded_output_wait.cpp - a duplicacao dessa MESMA espera em
# dois arquivos e' o que deixou o gemeo do defeito original vivo), mais
# src/platform/loop/loop_facade.cpp (LOOP-RUN fatia 6b, D-W6b-58): o
# giro de ate 1 ms de D-W6b-49 (`teto-nosso`) e as leituras de relogio
# que o step()/open() do laco fazem sem esperar nada (`nao-espera`).
#
# wl_display_roundtrip() (open()/roundtrip(), abaixo) e' `sem-teto-
# fora-do-caminho`: bloqueia de verdade, sem orcamento, mas SO' roda
# uma vez por open() ou por uma chamada explicita do consumidor a
# roundtrip() - nunca dentro do laco de quadro que pump_events()/swap_
# buffers() percorrem a cada frame.
