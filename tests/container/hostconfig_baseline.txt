# Measured baseline for check_isolation.sh's whole-block HostConfig
# compare (GODS_LAWS.md L-40, ISO-BASELINE). This is a live capture,
# not hand-written: `docker create --cap-drop=ALL --cap-add=SYS_NICE
# glintfx-wltest:latest` (the exact invocation the wayland-container CI
# job and this project's own docs use - no --security-opt, no other
# flag), then `docker inspect --format '{{json .HostConfig}}'`,
# normalized the same way check_isolation.sh normalizes the live
# measurement before comparing (see normalize_host_config()):
#
#   1. "ConsoleSize":[W,H] replaced with a fixed placeholder. This
#      field tracks the calling terminal's tty geometry (only ever
#      populated by `-t`, which this project's invocations never pass;
#      measured as [0,0] every time), not container security - keeping
#      it literal would make the baseline depend on who ran the
#      measurement from which terminal, for zero security benefit.
#   2. Each "/sys/devices/system/cpu/cpuN/thermal_throttle" entry
#      inside MaskedPaths removed (with its adjacent comma). Docker
#      emits one such entry per CPU core VISIBLE ON THE HOST RUNNING
#      DOCKERD - this machine has 16, a 4-core CI runner would have 4 -
#      and no `docker run`/`create` flag controls this list's cpuN
#      entries directly, so literal-comparing them would fail on every
#      host with a different core count, which is exactly the "alarme
#      constante que ninguem le" GODS_LAWS.md L-40 warns against.
#      check_isolation.sh does NOT drop this signal silently: it
#      separately asserts the STRIPPED entry count equals `nproc` on
#      the host running the check (assert_cpu_masked_path_count_matches_host),
#      which is what actually catches `--security-opt
#      systempaths=unconfined` (or any other flag that empties
#      MaskedPaths/ReadonlyPaths) - the exact failure mode this whole
#      fatia exists to close, invisible to the nine named fields the
#      previous version of this script checked (Mounts,
#      HostConfig.Devices, Privileged, PidMode, IpcMode, NetworkMode,
#      UsernsMode, CapAdd, CapDrop - none of which systempaths=unconfined
#      touches).
#   3. "OomKillDisable":false and "OomKillDisable":null both replaced
#      with the same placeholder. Measured live comparing ci.yml's own
#      two invocation shapes side by side on the identical clean
#      image: `docker create` (used for the three negative controls,
#      whose poisoned ENTRYPOINT deliberately never runs) reads back
#      `false`; the same container after `docker run -d` (used for the
#      positive control) reads back `null` - nothing else in the whole
#      block differs between the two states. Neither is a widening;
#      only the literal `true`, set by `--oom-kill-disable`, is, and
#      that is left OUTSIDE the placeholder match on purpose.
#
# The FIXED (non-cpu) portion of MaskedPaths and all of ReadonlyPaths
# are NOT normalized when this file was written: they are Docker's
# built-in default list for this Docker version and do not vary by
# host topology, so an exact-text mismatch in their CONTENT is real
# signal, not noise.
#
# ORDER-DRIFT (27/08/2026, GODS_LAWS.md L-40/ISO-BASELINE): their
# ORDER, unlike their content, is not something Docker promises to
# hold stable. The real `wayland-container` CI job (ubuntu-latest)
# reproved the positive control the first time it ran anywhere but the
# leader's own machine: same MaskedPaths entries as below, same count,
# just shuffled ("/proc/sched_debug", "/proc/scsi", "/sys/firmware"
# and "/sys/devices/virtual/powercap" swapping position with each
# other). check_isolation.sh's normalize_host_config() now runs
# sort_json_arrays() on BOTH the live capture and THIS FILE's own
# committed text before comparing them, so the JSON below is kept
# exactly as historically measured - it is NOT hand-sorted - and the
# compare is symmetric and order-independent purely at compare time.
# sort_json_arrays() is generic (any flat `[...]` array, not a named
# list), so it also covers CapAdd and CapDrop below, and every other
# flat string-array HostConfig field that is null/empty in THIS
# baseline but would populate as a scalar array if used: Dns,
# DnsOptions, DnsSearch, ExtraHosts, VolumesFrom, Links, GroupAdd,
# SecurityOpt, DeviceCgroupRules. It deliberately does NOT touch arrays
# that hold JSON objects (BlkioWeightDevice, BlkioDeviceReadBps/
# WriteBps/ReadIOps/WriteIOps, Devices, Ulimits, DeviceRequests when
# populated) - see check_isolation.sh's own comment on sort_json_arrays()
# for why that restriction is what keeps a smuggled device/mount
# breaking the match on content, same as before this fix.
#
# NULL-DRIFT (27/08/2026, GODS_LAWS.md L-40/ISO-BASELINE): a second
# runner-to-runner divergence, same root cause as ORDER-DRIFT one layer
# earlier - `docker inspect` promises neither a stable element ORDER
# for a populated array (ORDER-DRIFT, above) nor a stable choice of
# `null` versus `[]` for an UNSET one. Measured live: `"Dns":null`
# below (this file, captured on the leader's own machine) against
# `"Dns":[]` on a different `wayland-container` CI runner, same meaning
# (no DNS override was ever set) either way. check_isolation.sh's
# normalize_host_config() now rewrites any `:null` immediately before a
# `,` or `}` into `:[]`, applied to BOTH the live capture and this
# file's own committed text, so this file is kept exactly as
# historically measured (literal `null` where Docker produced `null`)
# rather than hand-edited to `[]` - see check_isolation.sh's own
# comment on that step for why a generic, unnamed rewrite is provably
# safe (it can only ever collapse two spellings of "nothing" into one;
# a populated array is untouched either way) and for the enumeration of
# the five other ways two builds could in principle spell an identical
# HostConfig value differently, done at the same time this fix was
# written.
#
# Measured 26/08/2026 against Docker Server version 29.7.2 (`docker
# version --format '{{.Server.Version}}'`) on the leader's Fedora 44
# machine, image glintfx-wltest built from this same commit's
# Containerfile. Re-measure and replace this file whenever the pinned
# Docker version genuinely changes the shape of `docker inspect
# --format '{{json .HostConfig}}'` for a clean container of this
# image - that re-measurement, and the raw diff it takes to notice one
# is needed, is the accepted cost this fatia's own text names.
